# ADR 0071: The README and its screenshots are updated at every release

- **Status**: Accepted
- **Date**: 2026-11-13
- **Supersedes in part**: [0070](0070-releases.md) (the list of steps)

## Context

The README describes what Tagwright does and shows it with screenshots. The interface changes often (the pipeline bar, the cover controls, the tag editor tabs), so screenshots and text go stale between releases.

## Decision

- Before the tag of a release is created, the README is brought up to date with that version: its description of the features, the run instructions and the variables table, and **every screenshot** in `docs/screenshots/` is retaken from the current build. New or changed screens (for example the cover menu or the pipeline bar) are added.
- Screenshots follow [ADR 0018](0018-verification.md): a scratch instance with synthetic albums (invented artists and albums, generated audio and covers), its own folders and data directory and a free port, at 1440 px width with a clean console. They never show the real library, real paths, real Discogs data or an API key.
- The release steps of [0070](0070-releases.md) get a step 0: update the README and the screenshots, and commit them with the changelog change. The commit's description says which screenshots were retaken.

## Consequences

- A release page, its tag and its README agree on what the program looks like.
- The screenshots are regenerated by hand from a scratch instance; no script is part of the repository yet.
